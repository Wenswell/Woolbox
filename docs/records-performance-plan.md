# Records 性能优化计划

状态：已确认，待实施  
范围：Android Records 根页读路径、相关服务端读接口与刷新体验  
目标：在一个应用进程内立即复用已加载的 Records 数据；以一个根页请求替代当前串行的五个请求；保持服务端为唯一事实来源。

## 已确认决策

| 项目 | 决策 | 原因 |
| --- | --- | --- |
| 缓存范围 | 仅进程内内存 | 解决底栏切换、独立页面返回和前台恢复时的等待，不改变 Records 的在线数据模型。 |
| 写入 | 仅在线写入 | 保持现有成功后服务端立即可见的语义，不增加队列、冲突处理或同步机制。 |
| 读取接口 | 新增根页聚合接口 | 根页是固定读模型；服务端一次读取比客户端编排多个接口更少网络往返和中间状态。 |
| HTTP 连接 | 保留一个进程级 `OkHttpClient` | 使用默认连接池和协议协商；不手工调连接池参数。公网入口已支持 TLS + HTTP/2。 |

不做：Room 或磁盘快照、离线读取/写入、重试队列、ETag、Paging、通用缓存框架、实时推送。

## 当前问题

1. `RecordRepository.refresh()` 串行请求活跃项、归档项、近 90 天流水、最新测量和待办，根页一次刷新需要五次网络往返。
2. `Records` 底栏切换、Activity `ON_RESUME` 和每次成功写入都会刷新；同一时刻的重复调用没有合并。
3. 已加载数据在刷新期间被根页 loading 状态替换，内存中的结果不能立即展示。
4. 根页不消费归档记录项，但刷新仍拉取它们；最新测量接口逐项查询数据库。

## 实施步骤

### 1. 服务端根页读模型

- 新增 `GET /api/overview?startDate&endDate`，只返回根页所需的：活跃记录项、待办（含子事项）、日期范围内的累计流水、每个活跃测量项的最新流水。
- 参数仍使用客户端固化的本地日期；Android 传入近 `STREAK_LOOKBACK_DAYS` 的起止日期，服务端不推断时区。
- 在 `RecordsService` 内以批量查询取得最新测量，删除逐项查询模式；接口响应不包含归档记录项。
- 保持现有单资源读接口，供 PC 管理页和测量 24 小时预览使用。

验收：Android 根页一次刷新只访问 `/api/overview`；响应字段足以计算今日累计、周目标、连击、任务进度和测量卡片最新值。

### 2. 原子内存快照与进程级网络客户端

- 将根页数据收敛为一个不可变的 Repository 快照，并在完整响应解析、派生计算完成后一次发布，避免多个 `StateFlow` 依次更新产生中间页面状态。
- 移除根页无消费者的归档项状态；编辑页仅从活跃项定位项目。
- 将 `OkHttpClient` 提升为进程级唯一实例。保留 OkHttp 默认 TLS、HTTP/2 和连接池配置，不增加自定义网络策略。

验收：同一进程内的所有 Records 请求由同一个 `OkHttpClient` 发起；一次根页响应只触发一次完整状态更新。

### 3. 刷新策略和页面状态

- 首次进入且没有快照时显示阻塞 loading；初次请求失败显示现有错误卡与重试。
- 已有快照时始终先显示快照。后台刷新只暴露 `isRefreshing`，不得替换根页、管理页或编辑页内容。
- Records 底栏切换不发请求；应用恢复前台时在保留快照的前提下刷新一次，以获取 PC 管理页等外部写入。
- ViewModel 维护单一进行中的刷新任务；新触发合并到该任务，避免重复读请求。
- 有快照的后台刷新失败时保留数据并显示可见的紧凑错误与重试入口；不得将内容清空或静默忽略失败。

验收：切换 `Records`、`Tools`、`Setting` 后回到 Records 不出现全屏 loading；连续恢复或重复触发只产生一个 overview 请求；后台刷新失败仍可查看上次成功数据并可重试。

### 4. 写后更新和按需预览

- 每次成功的记录项、流水、待办或子事项写操作后，执行一次 overview 刷新；页面继续显示现有快照，完成后原子替换为服务端结果。
- 测量 24 小时预览保持按需请求，不放入根页 overview；成功新增或撤销该项目流水后，只重新加载当前打开的预览。

验收：单次写操作后根页只额外请求一次 overview；Measurement 预览不会随根页刷新重复加载。

## 实施顺序

1. 服务端 overview 与批量最新测量查询，补充 API 测试。
2. Android Repository 快照、进程级客户端和 overview 解析，补充定向测试。
3. ViewModel 单飞刷新和首次/后台刷新状态。
4. 根页、管理页和编辑页改为保留内容的刷新反馈。
5. 完整构建、服务端测试、真机网络检查；把长期规则同步到产品、架构和设计文档并删除本计划。
