# Records 扩展计划

状态：实施中（测量记录与图表切片已完成代码与自动验证）

范围：单人在线 Records 的待办与测量值扩展

完成条件：两个纵向切片均通过验收；长期规则同步到主题文档后删除本计划。

## 目标与决策

在不引入通用任务系统、同步层或图表配置器的前提下，Records 提供：

1. 待办及一级子事项，显示可勾选的完成进度。
2. 任意频率的数值测量，支持指定发生时间和查看原始时间序列图表。
3. 保留现有累计记录、目标和连击语义。

| 原则 | 本次决策 |
| --- | --- |
| 第一性原理 | 待办是完成状态与清单关系；测量是带时间戳的数值样本。两者使用独立模型，不创建泛化实体。 |
| 基于现有证据 | `record_entries` 已保存发生时间和值，且 API 已支持范围查询；测量扩展复用该流水，不创建第二套时序表。 |
| 奥卡姆剃刀 | 仅两个根视图、一级子事项、四个固定图表范围。没有期限、提醒、重复、协作、标签、公式或图表配置。 |
| 破而后立 | Records 根页从单列表改为 `Tasks` / `Trackers` 页签；不保留旧入口或兼容 UI。现有记录项统一归为累计记录。 |

服务端 SQLite 继续是唯一事实来源；不新增本地 Records 数据库、离线队列或静默降级。

## 已确认产品规则

### Tasks

- 每个待办只有标题和零到多个一级子事项；子事项只有标题和完成状态。
- 无子事项的待办可直接勾选完成。
- 有子事项时，进度为已完成数/总数；父项勾选会在同一事务中勾选或取消全部子事项；全部子事项完成时父项完成，重开任一子事项时父项重开。
- 根页只显示未完成待办；已完成待办位于底部折叠区，可恢复、编辑或删除。
- 子事项按创建顺序显示；第一版不提供拖动排序、多级嵌套、期限、提醒、重复、优先级、项目、标签、附件或协作。

### Trackers

记录项新增 `ACCUMULATE` 与 `MEASUREMENT` 两种模式。

| 模式 | 输入与规则 | 首页与详情 |
| --- | --- | --- |
| `ACCUMULATE` | 沿用 `Number` / `Duration`、正数流水、目标、推荐时间段和连击。 | 沿用今日累计、目标与快速记录 Sheet。 |
| `MEASUREMENT` | 固定为 `Number`；单位必填；默认值可为空；步进必须为正有限数；流水可为任意有限数，包括零和负数。 | 显示最新值和时间；进入详情查看图表与流水。 |

- 新建测量值时，发生时间默认当前设备时间，保存前可修改日期和时间；保存时提交 `occurredAt`、`localDate` 与 `localMinute`。
- 测量详情只有 `24 h`、`7 d`、`30 d`、`All` 四个范围；X 轴使用真实发生时间，保留原始点，不补零、不聚合、不平滑。
- 点击数据点显示时间和值；详情的流水行可编辑值、发生时间或删除。
- 测量值不参与日/周目标、今日求和或连击。现有记录项在迁移时写为 `ACCUMULATE`，不改变既有数据语义。
- 图表使用 Vico Compose Material 3 所需模块；不手写坐标、手势或标记逻辑。

## 页面与路由

- `Records` 根页使用 `Tasks` / `Trackers` 页签，保留底栏的 `Records` 入口。
- `Tasks`：顶部加号新建；列表行包含复选框、标题、`N / M` 与细进度条；点击正文进入待办详情管理子事项。
- `Trackers`：保留 `Goals` 与 `Manage` 入口；项目卡正文进入详情，尾部加号执行快速记录。累计记录继续使用现有 Sheet，测量记录使用独立的值/时间编辑页。
- 图表详情使用标准路由骨架：返回、编辑、范围切换、图表、流水列表与新增记录动作。
- 页面继续组合 `TemplateComponents.kt` 的稳定组件；不在卡片内嵌卡片，不因页签切换改变操作语义。

## 数据、API 与代码边界

| 位置 | 变更 |
| --- | --- |
| `record_items` | 增加不可空 `mode`；迁移把已有行设为 `ACCUMULATE`。 |
| `record_entries` | 复用现有表；补充 `(item_id, occurred_at)` 索引和流水更新 API。 |
| `todo_tasks` / `todo_steps` | 独立表，保存标题、完成时间、创建/更新时间和父子关系；子事项删除随父项级联。 |
| 服务端领域层 | 按模式校验记录项与流水；任务/子事项状态切换在事务内重算父项完成状态。 |
| 审计 | 延续当前成功写操作同事务审计；新增 `TASK`、`STEP` 实体和对应动作。 |
| Android | 扩展 `record/model`、`RecordRepository`、`RecordsViewModel` 与 `record/ui`；不新增 Room 数据层。 |
| PC 管理页 | 记录项表单支持两种模式并隐藏不适用字段；Entries 继续只读/删除。第一版不新增待办管理页和图表。 |

服务端路由至少覆盖任务列表、创建/编辑/删除、任务完成切换、子事项创建/编辑/删除/完成切换，以及 `PUT /api/entries/:id`。所有写操作失败时不产生部分业务数据或审计数据。

## 实施顺序

### 切片 1：测量记录与图表

1. 已增加 `mode`、流水更新能力和迁移；服务端校验、范围查询与审计已有定向测试。
2. 已在 Android 模型、Repository 和 ViewModel 中区分累计与测量；测量值可编辑发生时间。
3. 已新建测量详情路由，接入 Vico 图表、范围查询和流水编辑；原累计记录路径保持其明确语义。

验收：可创建 `Temperature` / `°C` 测量项，录入 `0` 或负数及过去时间；详情按真实时间位置显示该点，改值、改时间和删除后立即刷新；累计记录仍按当前目标和连击规则工作。

### 切片 2：待办与子事项

1. 增加任务表、领域规则和 API，并为父子完成状态的原子更新添加服务端测试。
2. 增加 Android 任务模型、Repository 状态和详情路由；根页接入两个页签。
3. 实现任务创建、编辑、删除、子事项勾选及已完成折叠区。

验收：可创建无子事项待办并直接完成；可创建有子事项待办，任意子事项切换后进度与父项状态立即正确；任务重新打开、编辑和删除后服务端与 Android 一致。

### 收尾

1. 只保留复用后的 Records 入口与组件，删除被替代的页面状态和无效规则。
2. 将长期行为同步到 `docs/product.md`、`docs/architecture.md`、`docs/design-system.md`、`docs/development.md`；删除本计划。
3. 运行定向测试、Records server 验证、Android 默认提交前验证和 `git diff --check`。

## 验证边界

- Kotlin：模式校验、测量有限数与时间、任务完成派生、页面排序/文案。
- Server：迁移、模式约束、流水更新、时间范围、任务事务和审计。
- Web：记录项模式表单与现有 Entries 行为。
- 真机：Records 凭据、测量时间编辑、图表点位/标记、任务勾选与深浅色；无需无障碍窗口验收。

## 不做

- 多端冲突处理、离线缓存、导入导出、传感器自动采集。
- 周期任务、通知、到期日、日历、优先级、标签、项目和任务协作。
- 多层子事项、拖动排序、批量任务操作。
- 多系列图表、柱/饼图切换、公式、趋势预测、移动平均和可配置聚合。
