# 工具功能调整

状态：实现完成，正在测试和发布；真机验收等待连接设备。

## 范围和顺序

1. 核实并精简已有覆盖层尺寸修改，单独提交；Android 最低 API 31，使用 currentWindowMetrics。
2. 删除 Android Records、服务端代码、测试、专属依赖和文档，移除凭据与提醒入口。无需远端数据迁移。
3. 底栏改为扫一扫、Tools、Setting，默认扫一扫。
4. Global Copy 增加滚动采集模式：用户手动滚动，停止后采样，同一会话合并去重，回到编辑模式后支持现有编辑和复制。
5. 三个工具统一保存本地操作日志，提供列表、详情和导出。扫码记录来源、结果原文和复制/打开动作；全局复制记录会话、事件时间、原始采样、合并结果、去重原因和复制结果；OLED 记录参数、参数修改、启停和结束原因。日志保存在应用私有存储，通过系统文件选择器导出 JSONL；不上传。查看入口放在各工具页面，另在 Setting 提供全部日志入口。
6. 扫一扫支持相机和相册二维码识别，结果可复制；可打开的链接提供打开操作。采用 CameraX 和 ML Kit，沿用现有 Compose 结构。
7. 更新产品、架构、测试和使用文档，递增版本，完成构建、提交、debug 发布和真机验收。

## 验收

- 仓库及 APK 移除 Records 业务，启动进入扫一扫，Tools 保留 Global Copy 和 OLED。
- 滚动时目标应用可操作，停稳后出现新增文本；往返滚动相同内容不重复追加，日志能解释采样及去重结果。
- 退出会话、切换目标或服务解绑后停止采样并释放窗口；历史保留合并后的会话。
- 相机和相册均可识别二维码；拒绝权限、无二维码和无可用打开应用时有明确反馈；离开页面释放相机。
- 定向测试覆盖合并去重及生命周期相关逻辑；提交前运行项目规定构建检查，发布后完成设备验证。

## GitHub 发布调整

- 发布目标为公开仓库 Wenswell/Woolbox，使用 debug、release 两个固定 Release 标签。
- 各标签附件包含版本化 APK 和 latest.json，先上传 APK，再更新 manifest；保留历史 APK。
- App 固定读取当前通道 manifest，校验仓库、通道、文件名、大小和 SHA-256；支持 GitHub 的 HTTPS 附件重定向。
- 使用 GitHub CLI 发布，发布前检查登录与仓库；完成后以匿名请求验证 manifest 和 APK 200、大小。
- 递增版本到 0.1.51 (52)，运行更新测试及 debug/release 构建，提交后发布 debug。
- 模拟器已连接；继续扫码、日志导出和覆盖层验证，并记录硬件相机验证边界。
