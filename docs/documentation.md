# 文档维护

## 目标结构

| 文档 | 唯一职责 |
| --- | --- |
| `README.md` | 项目入口、能力概览、快速开始和文档导航。 |
| `AGENTS.md` | 仓库内 Agent 的执行约束和必读顺序。 |
| `docs/product.md` | 当前产品范围、功能规则、用户流程、状态语义和验收标准。 |
| `docs/architecture.md` | 当前系统结构、运行流程、模块契约、平台边界和数据规则。 |
| `docs/design-system.md` | 页面层级、可复用组件、视觉规则和交互规则。 |
| `docs/development.md` | 源码地图、环境、验证命令、设备验收和故障定位。 |
| `docs/documentation.md` | 文档职责、同步规则和质量标准。 |

短期实施计划可放在 `docs/<area>-plan.md`，必须标记状态、范围、顺序和验收，且完成后删除。已完成的迁移计划、修复计划和单次实施计划不作为当前事实来源；长期有效的结论应归入上述主题文档，重复内容删除。

## 信息归属

| 变化 | 必须同步 |
| --- | --- |
| 功能范围、业务规则、入口、状态或用户流程 | `docs/product.md` |
| 服务职责、命令流程、窗口解析、存储或平台边界 | `docs/architecture.md` |
| 页面结构、组件 API、样式或交互规范 | `docs/design-system.md` |
| 源码路径、依赖、构建、测试、设备验收或排障经验 | `docs/development.md` |
| 项目定位、技术基线或文档入口 | `README.md` |
| Agent 必读文档、编码约束或验证要求 | `AGENTS.md` |

同一事实只在一个主题文档完整说明。其他文档需要该信息时使用链接和一句上下文，不复制规则全文。

## 写作标准

- 记录当前事实，历史过程只保留会影响后续决策的原因和失败模式。
- 规则必须说明对象、触发时机、输入来源和结果；避免只写组件名或抽象结论。
- 命名、状态值、路径、默认值和时间参数与源码一致。
- 用户流程与实现流程分开：前者写可观察行为，后者写模块协作。
- 验收标准可执行、可观察，并与风险相称。
- 小型和中型主题文档控制在 `150` 行内；超过后按职责拆分。

## 当前基线

仓库文档按上述长期结构维护。`Global Copy`、`OLED shield`、`Records` 当前能力、Tile 触发、应用内触发及覆盖层 Context 边界均归入对应主题；进行中的 [Records 在线化计划](records-remote-plan.md) 在功能收尾后删除。

基线要求：

- README 可在一次阅读内说明项目用途、运行前提和下一步入口。
- 产品、架构、设计、开发信息没有职责冲突或大段重复。
- 页面入口与 Tile 入口、两项无障碍工具规则、Records 当前范围、目标窗口解析和覆盖层 Context 边界均有明确说明。
- 所有相对链接有效，文档中的源码路径和状态名可在仓库中找到。
- `git diff --check` 与项目默认验证命令成功。
