# Records 游戏化方案

状态：待确认  
范围：根页反馈增强（视觉与动效），不改数据模型、API、业务规则  
目标：让 Tasks / Accumulate / Measurement 根页更有进度感与完成反馈，保持工具应用克制

## 已确认方向

| 项 | 选择 |
| --- | --- |
| 类型 | 反馈增强：动效、触觉、短状态文案 |
| 优先面 | Records 根页总览 |
| 本轮 | 先文档，确认后再改代码 |

不在本方案：XP/等级、成就表、日任务配置、服务端新表、提醒、排行榜、Manage/Edit 全面皮肤化。

## 现状可复用

- Tasks：`N / M`、线性进度、色相卡、`Next ·`
- Accumulate：`64dp` 目标环、火苗目标/连击（`ItemStreak`）
- Measurement：最新值 + 时间、色相身份
- 色相：`recordItemColors(name)` 已统一

缺口：根页无「今日总览」；进度变化几乎无动效/触觉；完成与达标态与进行中态区分弱。

## 原则

1. 只增强已有进度语义，不发明新业务指标。
2. 反馈绑在真实状态变化上，禁止假进度或装饰性计数。
3. 动效短、可关（遵循系统「减少动态效果」时关闭装饰动画）。
4. 不扩路由；不改 Sheet/表单数据流；不改服务端。

## 切片

### 包 A：根页今日状态条（推荐第一刀）

在 `AppPageHeader` 与 Tasks 分区之间增加一行只读总览，数据全部本地派生：

| 字段 | 来源 |
| --- | --- |
| Tasks 完成比 | 未归档任务中「已完成父项数 / 全部父项数」；无任务则不显示该项 |
| 累计达标数 | 有目标的累计项中「今日/本周累计 ≥ 目标」的个数 / 有目标项数 |
| 活跃连击 | `current > 0` 的累计项个数；无则省略 |

展示：单行紧凑 chip/文案，如 `Tasks 2/5 · Goals 1/3 · Streaks 2`。  
不提供点击跳转（避免假导航）；无数据时整行隐藏。

验收：

- 有任务或有目标累计时出现；全空隐藏
- 数值与下方分区一致；刷新列表后同步
- 浅/深色可读；不挤压分区间距到难用

### 包 B：卡片进度动效与完成态

| 对象 | 行为 |
| --- | --- |
| Task 进度条 | `N/M` 变化时进度条 `animateFloatAsState`（约 200–300ms） |
| Task 全完成 | 卡面 accent 略强或完成勾号；`N/M` 仍显示 |
| Accumulate 环 | 累计变化时环进度动画；达标时环用完成色/对勾，保持火苗目标文案 |
| Measurement | 仅保留色相与主值；本包不加强（无「目标」语义） |

验收：

- 完成子事项返回根页后进度条平滑过渡
- 全完成任务与进行中任务一眼可分
- `reduce motion` 开启时无装饰动画，状态仍正确

### 包 C：交互瞬间反馈（根页触发路径）

根页打开的 Sheet 成功写回后：

| 事件 | 反馈 |
| --- | --- |
| 子事项勾选完成（未完成→完成） | 轻触觉 `ContextClick` 或 `Confirm` |
| 父项刚全部完成 | 稍强一次触觉 + Snackbar 短文案（如任务标题 + `done`） |
| 累计提交且达成本期目标 | 触觉 + Snackbar（项名 + `goal met`） |
| Measurement 提交成功 | 保持现有 Undo；不加庆祝（无目标语义） |

Snackbar 与现有 Undo 冲突时：Undo 优先；庆祝文案可并入同一条或省略。

验收：

- 仅状态真实变化时触发，重复点选不刷屏
- 失败无成功反馈
- 不引入新权限

## 非目标（明确不做）

- 经验值、等级、徽章库存、商店
- 改连击算法或目标规则
- PC 管理页游戏化
- 为动画单独加持久化字段
