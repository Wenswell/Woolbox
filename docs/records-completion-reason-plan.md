# Today 完成原因修复计划

状态：实施中

## 问题

`ENOUGH` 同时表示“完成四轮回顾”和“全部承诺完成”。界面统一显示完成轮次，因此承诺在首次回顾前完成时会出现“今天已足够、已完成 0 轮”的错误组合。

## 范围

- 每日计划新增必填 `completionReason`：活动过程为 `null`，进入 `ENOUGH` 时为 `ROUNDS` 或 `COMMITMENTS`。
- 第四次回顾写入 `ROUNDS`；全部承诺完成写入 `COMMITMENTS`；额外一轮或重置清空原因。
- 迁移现有 `ENOUGH` 数据：`completedRounds >= 4` 归为 `ROUNDS`，其余归为 `COMMITMENTS`。
- PC 与 Android 根据原因分别显示“今天已足够”或“今日承诺已完成”。轮次为零时显示“在首次回顾前完成”，不再使用“完成 0 轮”。
- 同步 API、审计快照、测试、产品、架构、设计和开发文档。
- Android 版本递增并发布 debug APK；服务端先于 APK 部署。

## 不包含

- 不改变一轮约 60 分钟、回顾时轮次加一、第四轮足量的规则。
- 不把完成步骤折算为轮次。
- 不增加目标轮数配置或新的恢复流程。

## 顺序

1. 扩展 schema、迁移、领域类型和状态转换。
2. 更新 PC 与 Android 的完成原因展示。
3. 增补服务端、Web、Android 定向测试。
4. 更新长期文档并删除本计划。
5. 完成全量验证、提交、服务端部署、debug APK 发布和发布记录。

## 验收

- 完成第四次回顾后为 `ENOUGH + ROUNDS`，显示完成四轮。
- 全部承诺在首次回顾前完成后为 `ENOUGH + COMMITMENTS`，显示“今日承诺已完成 / 在首次回顾前完成”。
- 全部承诺在已有回顾后完成时保留实际轮数，并显示承诺完成原因。
- 重置或开始额外一轮后 `completionReason` 为 `null`。
- 旧的 `ENOUGH + 0` 数据部署后自动归为 `COMMITMENTS`。
